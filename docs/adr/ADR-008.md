# ADR-008 — Separate reporting and administration experiences

Date: 2026-11-24
Status: Proposed — architect preference established; feasibility and stakeholder approval pending.

## Context
FR-05 through FR-08 require analytics, role-appropriate access and controlled configuration. Most users are assumed to consume reports; a smaller group manages sources, KPI definitions and exceptions. The actual audience sizes and licensing are unverified.

## Options considered
- Power Apps as a unified interface with embedded Power BI content.
- Power BI as the primary interface with embedded Power Apps actions.
- Separate reporting and administrative experiences sharing a governed data platform.

## Architect recommendation
Prefer separate experiences. Reporting users need analysis; authorized stewards and platform administrators need controlled operational actions. One interface need not serve every role. This reflects different governance responsibilities across departments and organizational levels.

## Candidate component responsibilities
Power BI: analytics and reporting. Power Apps: configuration and exception management. Dataverse: candidate shared data platform. Power Automate or dataflows: candidate ingestion and orchestration. These products are not yet formally selected. Integration must operate without either user interface being open.

## Trade-offs
Separate experiences reduce unnecessary UI complexity and may limit application licensing needs, but introduce separate navigation, access management, deployment and testing responsibilities. Interface separation is not a security boundary; enforce authorization in the underlying services and semantic model.

## Validation
Confirm audience workflows, licensing, connector support and access model. Demonstrate independent ingestion, authorized configuration updates, manager-scoped reporting and denial of unauthorized access. Map evidence to FR-05–FR-08, NFR-01 and NFR-04, and tests T06–T11 as applicable. Consult the companion governance framework before approval.
